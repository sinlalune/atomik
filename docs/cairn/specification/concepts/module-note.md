# Module note

A module note explains the current responsibilities, boundaries, data flow,
important files, tests, and known limits of one implemented area.

In Cairn, module notes live under `docs/modules/` and change with the source
area they describe. They help a future path enter the code through maintained
knowledge rather than rediscovering structure from scratch.

A module note is not [architecture](./architecture.md) authority when an
accepted architecture page or [decision record](./decision-record.md) says
otherwise.

Related: [architecture](./architecture.md), [work unit](./work-unit.md),
[project memory](./project-memory.md).
