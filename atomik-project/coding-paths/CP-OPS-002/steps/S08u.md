ADR-020 stage 5. `tools/cairn-init.mjs` installs Cairn into a repository:
schema-1 configuration, the reference tools, the portable protocol corpus, a
generated host binding and bootloader, the folder skeleton, a tier-1 workflow,
the one-concept template, and `cairn.lock.json`.

It installs the shapes the protocol states **now** — born-sliced records, and a
no-rewrite path history whose retention namespace is absent rather than
scaffolded and unused. That is the whole reason S08q reconciled the seed and
S08r/S08s removed the rebase before this command was written: an initializer
compiles the current shapes into the one artefact whose output nobody can
retroactively correct.

## What it actually proved

The first end-to-end run installed cleanly and then **failed its own first gate
with seventeen broken links**. None of them is visible from inside this
repository, where every target exists.

- **The portable corpus was not portable.** The specification linked the
  decisions that settled it — `../../adr/ADR-021` and friends — and those
  decision records cite this host's own planes: `atomik-project/`,
  `docs/bedrock/`, session notes. Installing the ADRs only moved the boundary:
  their transitive closure is nine records, and they dangle into host state.
  A decision record is a HOST artefact. It names a repository, a date and who
  accepted it, and rewriting one to hide where it was decided would be a
  forgery. So portable text now NAMES a decision — **ADR-021** — and does not
  link into a decision plane that resolves in exactly one repository.
- **One concept article linked host architecture directly**
  (`instruction-parity.md` → `bedrock/26`), inside the corpus S08o declared
  portable. The portability test at the time checked one reference page for the
  host's name; it could not see a link.
- **The portable path convention linked this repository's own history**
  (`paths-history.md`). That pointer moved to the binding, where host history
  belongs.

Nine outward links in total, now zero, and `outwardLinks()` refuses to install a
corpus that has any. The command is a portability test that runs.

## Three defects it found in itself

- Shipping a hand-written `ACTIVE.md` failed `derived-view` — an installer
  writing a derived file by hand commits the defect the protocol names. It now
  installs a scaffold with the splice markers and runs the generator.
- No `package.json`, so every `npm run` command the generated bootloader named
  did not exist.
- The one-concept template was named `_template.md` and read as an orphan
  concept: the rule's link pattern is `[a-z0-9-]+\.md`, so a leading underscore
  made every link to it invisible. Renamed, and linked from the binding — which
  is outside the concepts folder, which is what the rule requires.
