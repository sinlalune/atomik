[ADR-020](../../../../docs/adr/ADR-020-protocol-context-weight.md) migration
stage 2. `CP-OPS-002.md` is a folder, and this record is the worked example the
ADR asked for.

```text
CP-OPS-002/
  index.md      declaration · why · step index · documentation coverage · live header
  plan.md       S08's four parts and S09 — explanatory until executed
  log.md        the OKF folder log
  steps/        39 step records + index.md + log.md
```

**What moved, and nothing was summarised.** Thirty-nine steps became one file
each: S00–S07p came from `coding-paths/history/`, where the older rollup
convention had put them, and S07q–S08k came out of the live record. The
seventy-four-row Work Ledger dissolved exactly as decision 4 said it should —
**ten** live rows stayed in the header, **sixty-three** step-scoped rows went to
the steps they describe under a `## Ledger rows` heading naming where they came
from, and `Steps complete` became the per-step commit index in
[`steps/index.md`](./index.md), which is what an index over steps is for. A
sub-step's rows went to the step file that holds it: `S06d` is inside `S06`.

The required read is now `index.md` alone. `ledger-size` stopped firing — not
because the rule was switched off, but because the file it was speaking to no
longer exists. That is the whole argument of decision 4, observed rather than
predicted.

**Then the migration found three rules that knew a record by its address.** All
three fired, all three were right about the evidence they had, and all three were
the same substitution this path keeps finding:

| Rule | What it said | What was true |
| :-- | :-- | :-- |
| `registration` | `CP-OPS-002` was never registered on the trunk | registered 2026-08-24; the lookup used this checkout's file path |
| `transition` | the declaration was deleted without archiving | it moved to `CP-OPS-002/index.md` and declares the same id |
| `record-integrity` | 23 append-only records were destroyed, 23 unaccounted arrivals | 23 records moved, verbatim |

**A record's identity is the id it declares, not the file that carries it.** All
three now key on the id, and `pathFrontmatterErrors` reads the folder segment
rather than the last one — otherwise every migrated record is told its id is
`index`.

**Relocation needed a predicate, and it is exact rather than a similarity
score.** Two operations are sanctioned on a record that moves: repointing a link,
because a link is an address rather than content and the same target must keep
resolving; and appending, because that is how a record grows without an earlier
sentence changing. So `isVerbatimRelocation` normalises every link target away
and requires the old text to be a **prefix** of the new. Measured before the rule
was written: all 23 relocations satisfy it, none by accident. The frontmatter
sits at the very start, so the same test stops a relocation from quietly changing
which record it claims to be. **The exemption is stated, not silent** — an
advisory names the relocations on every run, because an exemption nobody can see
is indistinguishable from a rule nobody enforces.

**Two holes the migration would otherwise have opened**, both found by asking
what the rules read rather than by watching them pass:

- `isImmutableRecord` protected `history/` and would not have protected
  `CP-<id>/steps/`. Thirty-nine records would have become editable in silence.
  A record does not stop being append-only by moving house.
- `parseWorkUnits` read the declaration file, which after slicing holds no
  `cairn-unit` block at all. A path that has completed thirty units would have
  reported zero, disarming `work-unit` **and** `checkpoint-retention` together.
  The record is the folder, so the ledger is every step file in it, read in
  ordinal order — directory order is not chronology, and "the newest unit" is
  what the retention exemption turns on.

**`ledger-size` is NOT retired**, which the ADR schedules for stage 3. It now
applies to flat records only, and it is the sole signal a record that has not
been sliced ever gets: `CP-MVP-008`, `CP-MVP-011` and `CP-MVP-012` are still
flat. Retiring it now would remove the rule at the moment it still has something
to say. It goes when the last flat record migrates.

Doctrine followed the decision in the same unit: `paths.md` §*The path record is
a folder, born sliced* replaces §*The ledger has a boundary*, the specification
states the folder shape and the relocation predicate, and the
`record-integrity` concept note gains §*Relocation is not mutation*. Twenty dead
anchors to the retired heading were repointed. `history/index.md` keeps its
CP-OPS-002 entries, repointed and marked MOVED — an index that forgets where
something went is worse than one that says.
