S09's first unit. A research-paper workspace was created by `cairn-init` and
driven, by hand, from the installed pages, through every state a path can
reach. Run 1 stopped at closure: no honest closing record could pass the gate.
Nineteen findings, ten of them checker predicates, were repaired or stated;
run 2 on the repaired kit reached `done` with zero red gates. The record is
[`docs/cairn/cairn-greenfield-pilot-2026-09-01.md`](../../../../docs/cairn/cairn-greenfield-pilot-2026-09-01.md);
this file says what changed here and why.

## The shape, again

Every one of the ten predicate defects is the substitution this path has been
naming since its audit: a proxy read for the sentence the rule states.

- `git status --porcelain` lists a **directory** where the rule needs its
  files, so a born-sliced record — the shape the protocol prescribes — was
  invisible at registration. Measured: opening acceptance removed, gate OK.
- `closure-surface` read the **trunk's** copy of the record where acceptance
  was measured against the **candidate's**, so a `writes:` widened while
  running was a closure change. This repository's own closure would have hit
  it, at a point where the only remedy is to lie about the widening.
- `acceptance` read `String([])` for a **list**, and a **count of commits** for
  the closure being prepared in the working tree — blocking on the count while
  judging none of the files.
- `advisory-disposition` assumed **A ⊂ C** for advisories that only exist at A:
  the closing record's own `role-collapse`, `scope-drift` on the audit and
  closing record every closure adds, `remote-checkpoint` about the closure
  commit before its push, `single-truth` over a view the closure must
  regenerate. An honest attestation of C's advisories was rejected four ways.
- `derived-view` demanded the regenerated view at `ready` and the closure file
  set admitted it at `done`: no edit reached `ready`.

## What changed

- **`tools/cairn-check.mjs`.** `--untracked-files=all` at all three status call
  sites; the registration probe's stderr piped; the closure file set admits the
  generated view at every closed status and the record folder's `log.md`; an
  uncommitted closure counts as the pending administrative commit and its files
  are judged; an empty disposition list is a list; closure-raised advisories
  (`role-collapse`, `remote-checkpoint`) are excluded from the attestation
  subset and still reported; lifecycle records — opening, closing, audit,
  journal, brief — are not scope drift; `closure-surface` compares against the
  record at `subject_commit`; `single-truth` skips a generated view that equals
  its generator's output; `--scope-digest <file>#<anchor>` prints the digest the
  checker verifies; one host citation removed from a message.
- **`tools/cairn-audit.mjs`.** *"bedrock page and ADR"* → *"architecture page
  and decision record"*, in the shipped scaffold and its header comment.
- **`tools/cairn-rules.mjs`.** The `closure-surface` condition now states what
  the code enforces — `status` and `subject_commit` at `ready`, plus
  `resolution` at `done` — against the candidate's copy.
- **`tools/cairn-fixture.test.mjs`.** `readyRepository()` builds a real closed
  candidate: session-note opening, a unit that widens `writes:`, a bare remote
  pushed, the real audit scaffold filled, an honest closing record, and the
  administrative edits uncommitted. Its green baseline is the regression test
  for findings 10–15, 17 and 19. Five rules leave `UNCOVERED`:
  `closure-surface`, `acceptance`, `scope-digest`, `coherence-audit`,
  `advisory-disposition`. A sixth fixture writes a running record into an
  untracked folder with no opening acceptance and requires
  `opening-ceremony` to block; a seventh asserts the committed, unpushed
  closure is green and still reported.
- **Portable corpus.** The path template no longer links an unwritten step and
  its *Becoming ready* regenerates the view and appends the folder log; the
  operations page computes the digest with the tool, regenerates the view at
  A, runs the gate before the closure commit, and stages six surfaces; the
  human-records page says which record names which `base` and that the
  combined lightweight forms are not yet accepted; the handoff-brief page
  states the first-unit checkpoint convention; the lightweight-path and
  coherence-audit concepts and two normative passages say the three reliefs
  are stated, not implemented; the matrix row for the route carries the gap
  and the closure-surface row matches the code. Catalogue, linkage and the
  universal reader regenerated.
- **Widening.** `writes:` gains `tools/cairn-fixture.test.mjs`,
  `tools/cairn-init.mjs` and `tools/cairn-init.test.mjs`, which S08u and S08v
  created while the gate advised on them; the declaration now describes the
  work.

## Not done, and said so

- **Finding 7**: nothing predicates the brief refresh. A `brief-stale` advisory
  is the obvious rule and it is not added here — this path's own directive is
  fixture before rule.
- **Finding 16**: the initializer names an area note it does not create.
- The lightweight route's three reliefs remain unimplemented; the pilot paid
  the full route's cost on the default route and the number is in the record.
- The trunk never moved during the pilot, so acceptance drift and a conflicting
  integration remain unexercised outside the fixture suite.
