S08q reconciled the seed and, in doing so, showed the apparatus propagating: the
generation notation had to be pushed into the layout reference, the operations
sequences, the repair procedures and the template, so that every future adopter
would inherit it. That is the moment to ask what it is for.

It is for the rebase. The retention namespace, its generations, the derived
current generation, the three-state verdict and the non-default fetch refspec are
all downstream of one mandatory operation, and none of them is protocol — they
are compensation for rewriting the commits the ledger names.

`ADR-021` considered forbidding rewriting and rejected it as the default for one
reason: the rebase gate lets self-merge work without an integrator, because
requiring the branch to contain the trunk tip serializes the merge without
serializing the work. **That argument does not distinguish rebase from merge.**
Merging the trunk into the branch also makes the branch contain the trunk tip,
and the serialization comes from the push being rejected when the trunk moved —
which is identical either way. The rationale selects a property both operations
have; it never asks for the rewriting that only one of them requires.

`ADR-022` is accepted on that gap. Path branches are not rewritten, a current
base is reached by merge, and retention is disabled by configuration rather than
deleted — it remains the correct design for a host that keeps rewriting, so
`ADR-021` stays accepted and is superseded only as the DEFAULT.
