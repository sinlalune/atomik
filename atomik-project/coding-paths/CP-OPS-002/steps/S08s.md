# CP-OPS-002 S08s

### S08s — Rewriting stops, and the policy becomes a predicate — **COMPLETE**

```cairn-unit
step: S08s
unit: 39
type: implementation
verified: cairn-check, cairn-check:test, cairn-active, cairn-spec:build, typecheck, test, build
```

`ADR-022` is landed. `cairn.config.json` declares `checkpointRetentionRef: null`
and `pathHistoryPolicy: forbidden`, the pair the schema-1 loader already
validated together, so the retention predicate is disabled by configuration
rather than deleted from the checker.

Disabling a rule is not the same as replacing it, and the difference is the
whole unit. A policy that exists only as a configuration field is a claim, and
unchecked claims are what this path was opened to find — so `path-history` now
blocks when the branch's own upstream is not an ancestor of `HEAD`. Three shapes
are distinguished and only the third is a violation: `HEAD` reachable from the
upstream is published, the upstream reachable from `HEAD` is the ordinary
unpushed commit, and neither is divergence — a rebase, amend, soft-reset fold or
force-push of work that was already published.

## Two things the flip exposed

**The reference implementation was one config field away from being untested.**
Flipping the binding broke fourteen retention tests, because they built ref names
from the host's live prefix and inherited its enable flag. `ADR-022` keeps
retention as the correct design for a rewriting host, so a test suite that only
runs while this repository enables it would leave that design unexercised from
the moment it was disabled. `retentionGenerations` and `evaluate` now take the
prefix as a parameter, and the retention fixtures supply their own.

The same fault sat in `cairn-config.test.mjs`: its retention/policy pairing test
started from the live binding and mutated one field, so it silently changed
meaning the day that binding flipped. It now states both directions explicitly.

**The `rebase` rule was telling operators to commit the violation.** Its
condition — the branch must contain the trunk tip — is exactly what `ADR-022`
preserves, and is the property that serializes the merge without an integrator.
Only its REMEDY was wrong. The rule id is kept, because audits and recorded
advisory dispositions name it, and the remedy now follows the declared policy.
