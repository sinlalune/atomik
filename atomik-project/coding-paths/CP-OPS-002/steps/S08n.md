# CP-OPS-002 S08n

### S08n — An append is not a rewrite, and the baseline belongs to the record — **COMPLETE**

```cairn-unit
step: S08n
unit: 34
type: repair
verified: cairn-check, cairn-check:test, cairn-rules, cairn-spec:build, typecheck, test, build
```

The finding left by [S08m](./S08m.md) offered two choices: freeze a step
record when its commit is pushed, or establish it only when it reaches the
trunk. The measured edit made that a false dilemma. Commit `b8f89bf` appended
one row to the END of `S08m.md`; it changed no earlier byte, and the normative
specification already says a step record is **append-only wherever it sits**.
The checker was substituting Git status `M` for *earlier content changed*.

GitHub Actions carries the exact evidence. Run
[`33495928173`](https://github.com/sinlalune/atomik/actions/runs/33495928173)
compared `b8f89bf` with `9b3a6d1` and failed only `record-integrity`, calling
the suffix append a forbidden modification. Run
[`33496071795`](https://github.com/sinlalune/atomik/actions/runs/33496071795)
compared `f9cea35` with `b8f89bf`; `record-integrity` disappeared and the run
failed only because `b8f89bf` had no retention ref. The local default at
`f9cea35` reproduced that second failure. One branch state had forgotten a
question the preceding CI run asked, while the question itself was wrong.

**The repair reads the record, not the status code.** For every born-sliced
step in the branch diff, `record-integrity` follows renames to the commit and
path that ADDED it. In place, that adding blob must remain an exact byte prefix
of the current file. During a step relocation only, relative link targets may
be repointed and the normalised old text must still be a prefix. Therefore:

```text
old text + suffix       pass   append-only growth
earlier byte changed    fail   rewrite
old text truncated      fail   rewrite
session/audit rename    fail   immutable event identity moved
```

The adding blob is stable across local and CI invocation contexts; `HEAD`, the
prior push and the trunk merge-base are not. A valid S08m suffix append now
passes both contexts, while a deliberate frontmatter-byte edit was run through
the live gate and rejected by `record-integrity` before being restored.

The conformance claim moves only as far as the predicate. Born-sliced step
prefixes are proved. A flat live ledger and a byte-for-byte roll still lack the
markers needed for the same proof, and the checker does not reconstruct an
intermediate rewrite that was later restored to the adding-blob prefix. Those
limits remain stated instead of being hidden by the repair.
