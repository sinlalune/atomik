# CP-OPS-002 S08p

### S08p — The host binding becomes executable — **COMPLETE**

S08o separated portable protocol from Atomik's human binding, but the three
reference commands still carried a second, executable binding as constants.
Changing a trunk name, project root, metadata key, source root, area note or
checkpoint policy in the documented adapter therefore changed no verdict. The
configuration contract existed and the implementation truthfully called it
unimplemented.

This unit installs schema 1 at repository root and makes it the only executable
host binding. `tools/cairn-config.mjs` loads it before repository rules run,
rejects unknown versions and fields, rejects unsafe or non-canonical paths,
checks retention-policy consistency, and exposes the resolved repository root,
metadata block and path helpers without a package dependency. The companion
JSON Schema gives editors and future generators the same public shape.

The checker, live-path generator and audit scaffold now consume that binding:

- trunk, remote, enforcement profile, metadata namespace, documentation,
  project, architecture, decision, module, concept and source roots come from
  the configuration;
- ordered area routing carries an explicit name, one or more globs, and the
  exact module note, instead of reconstructing a host filename from an area
  nickname;
- shared files, staleness, the default route, digest algorithm, retention ref
  prefix and the finite legacy sets come from the same file;
- `pathHistoryPolicy: forbidden` is the explicit alternative to retention and
  disables the ref predicate only when the null-prefix pair validates;
- the checker prints the effective profile and binding with every ordinary
  verdict and includes the same structure in JSON output;
- audit templates use the configured metadata key, accept the repository's
  full SHA-1 or SHA-256 object ids, and discover both flat and born-sliced path
  declarations.

The configuration binds the concept-wiki role now, so the teaching axis is not
something an initializer must guess. It does not pretend that naming a folder
is the pedagogical scaffold: the index separating borrowed from defined terms
and the one-concept page template remain explicit `cairn-init` deliverables.
