S08 Part 2. Until this unit the checker's suite exercised valid inputs and
asserted `OK` — which a rule wired to nothing also satisfies. The conformance
matrix said exactly that about itself, and it stayed true for the whole path.

`cairn-init` made the fix affordable. Each fixture installs a REAL repository,
proves it green, introduces exactly ONE violation, runs the REAL checker as a
subprocess, and requires that rule among the blocking findings.

**The green baseline is half the assertion.** A fixture that blocks for an
unrelated reason proves nothing about the rule it names, so every fixture
asserts an empty blocking set first. Reaching that baseline on a path branch was
most of the work: a registered record, a regenerated live view, and a conforming
handoff brief with its nine fields and seven sections.

## What the fixtures found

- **`route` cannot fire on the trunk.** The first version added a path record
  with an unknown route to `main` and expected a rejection. The rule is guarded
  by `onPath && match`, so it never evaluated. The trunk fixture was deleted
  rather than weakened, and a path-branch fixture replaced it — a fact about the
  rule discovered by trying to make it reject something.
- **A committed mutation is invisible to a diff-scoped rule.** The first
  fixtures committed their violation, so the default run compared a working tree
  against `HEAD` and reported `0 changed file(s)`. Every diff-scoped rule stayed
  silent on a repository that plainly violated it. Mutations now stay in the
  working tree.

Both are the same lesson: an assertion about a rule that never ran is worth
nothing, and only an adversarial fixture can tell the difference.

## Coverage is declared, not counted

Eight of thirty blocking rules are covered. The other twenty-two are listed
explicitly in `UNCOVERED`, and a test requires every blocking rule to appear in
one list or the other — so adding a rule forces the choice rather than quietly
lowering a percentage nobody reads.
