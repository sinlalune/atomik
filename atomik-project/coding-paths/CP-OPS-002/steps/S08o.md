ADR-020 decision 3 classified every entry artefact as PORTABLE, HOST or
BINDING. Before this unit the classification existed only in the decision:
Atomik's product constitution was still an unconditional fourth read,
bedrock 22 still contained the portable session procedure under host
frontmatter, `paths.md` interleaved required rules with pilot history and local
examples, and the portable repository reference was the one sanctioned place
that named `atomik-project/`. The file tree still taught the boundary it had
decided against.

**The entry chain now has two portable parts and one adapter.**

| Classification | Current artefact | Owns |
| :-- | :-- | :-- |
| PORTABLE | [`paths.md`](../../paths.md) | path registration, isolated writers, work units, retention, session boundaries, exact-candidate integration and cleanup |
| PORTABLE | [Cairn execution protocol](../../../../docs/cairn/specification/reference/execution-protocol.md) | the ordered procedure for entering, advancing, handing off, resuming and closing one path |
| BINDING | [`binding.md`](../../binding.md) | Atomik roots, `master`/`origin`, npm commands, worktree dependency links, `ATOMIK_LANE`, product hot files and host-only invariants |
| BINDING | repository-root [`AGENTS.md`](../../../../AGENTS.md) | the short ordered pointer to those three artefacts plus the absolute rules that must survive truncation |
| HOST | [bedrock 00](../../../../docs/bedrock/00_00-orientation.md) | Atomik's product constitution, selected through documentation coverage rather than read merely because a coding session starts |

Bedrock 22 remains at its stable host address, but it is now a pointer rather
than a second execution protocol. Its former combined text is retained
unabridged under `docs/bedrock/archive/`. The former 533-line path page is
likewise retained as `paths-history.md`, while the required `paths.md` is the
portable operating route. Separation removes explanation from required reading
without shortening or deleting it.

**The specification no longer carries an installed host inside its portable
pages.** The Atomik mapping moved out of the repository-layout reference and
the configuration example now uses role-name defaults. Canonical, concept and
reference Markdown contain no `Atomik` occurrence; the single human-readable
installed mapping is the binding appendix. The generated universal reader
includes the new execution page automatically.

The contract is executable. The specification suite now rejects an Atomik name
in any portable reference article, checks that both portable entry documents
declare their classification, checks that the bootloader names the binding and
does not put bedrock 00 back in its start route, and pins the extracted runtime
and hot-file examples to the binding instead of merely checking that they
vanished.
