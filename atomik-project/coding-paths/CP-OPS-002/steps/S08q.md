### S08q — The seed teaches the shape the protocol states — **COMPLETE**

ADR-020 stage 5 begins by reconciling the seed, and the reconciliation turned
out to be the finding. The canonical text has taught born-sliced path records
since the folder migration and generation-aware retention since `ADR-021`. The
pages an adopter actually copies from had not moved with it: the layout
reference drew `checkpoints/<id>/<n>` and a flat `CP-<ID>.md`, the operations
sequences retained into an ungenerated namespace and never opened a generation
after the rebase that closes one, the repair procedure restored moved refs into
the flat namespace, and the template was a single file with an inline Work
Ledger. Two flat notations had also survived inside the canonical index itself.

This is the same substitution this path keeps finding, one plane up. Every
earlier instance was a predicate reading a proxy for the sentence its rule
states; this is a **seed** teaching a shape the specification has already
superseded. It would have been invisible until an adopter used it, and then it
would have been unfixable in their repository, because what `cairn-init` writes
on day one is what they own from day one.

The reconciliation is therefore a prerequisite of `cairn-init`, not a tidy-up
beside it. Writing the initializer first would have compiled the superseded
shapes into the one artefact whose output nobody can retroactively correct.

## What moved

- **`repository-layout.md`** — the reference tree gains the `g<NN>/` level and
  the `CP-<ID>/` record folder with `plan.md` and `steps/`; the roles table
  gains the born-sliced record, its append-only step file, and the flat record
  named as the older conforming shape; the namespace section states that the
  current generation is derived and never stored, and that pre-notation refs are
  never moved into one; path identity shows both shapes as one id.
- **`operations.md`** — checkpoint retention writes `g01/01`; pre-rebase
  retention stays in the generation still current; and the rebase sequence now
  opens `g<NN+1>` from the rebased branch before the rewriting push completes.
  The worked example writes a born-sliced record, including the step file the
  work unit stages.
- **`repair.md`** — both recovery procedures name the generation, and repair
  happens inside the generation a ref belongs to.
- **`path-template.md`** — the template creates a folder. `index.md` carries the
  live header, forward steps move to `plan.md`, the Work Ledger dissolves into
  one file per step, and the step file is shown as its own record with its own
  frontmatter.
- **`index.md`** — the two surviving flat notations are corrected. No other
  normative text changed; the canonical position was already right.
