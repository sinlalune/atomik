#### ADR-023, verified rather than assumed

The path's third outcome was whether the held patch survives an `update`:

```text
tools/cairn-check.mjs   git diff  → empty, untouched
                        recorded digest == on-disk → False, so it reads edited
                        `linkExempt` present       → True
```

The mechanism ADR-023 documents holds under the command it was written about.
`update` keeps an edited kit file, and the lock goes on reporting it edited
because the recorded digest is the release's, never the host's.

#### What `update` did to the lock, which is the finding

The lock changed **fifteen** manifest digests, at the same release, the same
`sourceCommit` and an unchanged configuration. Every one is accounted for:

```text
  11  the date stamp                 6 untouched, expected digest re-rendered
                                     5 rewritten for nothing but their own date line
   2  ACTIVE.md, cairn.config.json   re-baselined to THIS HOST's bytes
   2  pull_request_template, README  real content
```

The eleven are one mechanism: every templated file is rendered with today's
date, so the digest of what the kit *would* write depends on when you ask. Two
runs on two days produce two locks from one repository in one state.

The two re-baselines are a different mechanism — the recorded digest became the
host's current bytes with neither file rewritten, taking the edited count from
twelve to ten. For `cairn.config.json` the kit does this deliberately and says
so in its own comment; it has no timestamp to render, which is what proves the
two causes apart.

**This unit's first draft accounted for nine of the fifteen**, named the two
re-baselines as the finding and missed the eleven. The six untouched ones are
invisible unless the manifest is hashed against the tree, which is what a
reader did and this record had not.

All of it is filed upstream as
[cairn PR #29](https://github.com/sinlalune/cairn/pull/29), whose own first
draft then swung the other way and put all fifteen on the clock — corrected
there too.

#### Two defects in what the kit wrote

- `.github/pull_request_template.md:45` — `- reviewer: <who approves>, holding
  the roles <initiator | writer | reviewer | integrator>` is the one blank in
  the file that is not backticked, in a file whose own header explains that a
  bare `<tag>` is stripped by the forge *"leaving a blank that reads as
  answered"*. Rendered, it becomes `reviewer: , holding the roles  on this
  path`. The defect the header exists to prevent, in the header's own file.
- `tools/cairn-audit.mjs`'s docblock says the kit's generated template *"does
  not carry these sections yet"*. This update made that false: the installed
  template carries both, and the two copies already differ in wording. The
  template's own coherence question — *is anything now documented in two places
  that will drift apart?* — answers yes about itself.

Both are the kit's, and both go to the feedback channel rather than a fork.
