#### Work

```cairn-unit

```

- `docs/modules/application.md` claims no area. It is three lines pointing at
  the folder index, which already lists every area and its note.
- **It is edited rather than deleted, and the reason is the point.** The file
  is kit-owned and was **pristine** — the only pristine one this unit touches.
  The release rewrites a host file that still holds exactly what the kit wrote
  and never rewrites one the host has edited, so deleting it is the shorter
  diff that does not survive the next `update`. Editing is the only expression
  this release gives a repository for *the kit's default does not fit here*;
  that `update` cannot decline a host file is already on Cairn's 1.2 row, and
  this is what living without it looks like.
- `cairn-postmortem` has a caller: a `package.json` script, a line in the
  mechanical contract of both `AGENTS.md` and `binding.md` — which S03
  deliberately withheld until the script existed — and the
  postmortem-on-failure step the release's own installed workflow carries,
  with the `permissions` block it needs (`contents: read`, `actions: read`,
  `pull-requests: write`) and the `id: cairn-check` the `if:` condition reads.
- the step runs only on the checker's failure, prints, and commits nothing. A
  branch has one writer and it is the writer of the path, never a job.
