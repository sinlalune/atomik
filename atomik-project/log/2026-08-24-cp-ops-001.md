# CP-OPS-001 — coding paths run in parallel and carry their own remote memory

CP-OPS-001 opened because one active coding path had become one execution
lane: progress on the roadmap, feedback repairs, provider work and UI polish
could not proceed together without abandoning the coherence guarantees the
path protocol provided. The surviving answer is smaller than the first design:
a coding path itself is the parallel unit, one branch and one worktree per
writer, and every path closes and merges itself.

## What landed

The first steps isolated the resources Git worktrees do not isolate. Electron
instances receive lane-specific user-data profiles and dev-server ports before
app readiness, while project-relative `.atomik/` state remains naturally
checkout-local. The 1,600-line desktop module note was split into area-owned
notes so unrelated paths no longer collide in the same prose file.

Cairn then made the workflow executable:

- `paths.md` defines path-per-worktree execution, advisory declared writes,
  opening/closing ceremonies, rebase serialization and self-merge;
- `cairn-check` is a dependency-free protocol validator, separate from product
  gates in the repository's CI workflow;
- `cairn-active` generates the live running-path projection;
- `cairn-audit` gives the agent a durable architectural-drift checklist whose
  existence is checkable while its judgment remains advisory;
- the journal is one file per integrated path rather than a shared append;
- D13/D14 and the layered Cairn guide make the complete workflow inspectable.

## What challenge removed

The first proposal overestimated shared-file danger and introduced an
integrator plus a lane layer. The owner challenged both. Four real merge
experiments showed three feared conflicts either conflicted visibly or merged
correctly; only a shared global-state sentence could merge into a silent
contradiction. The false blocking rule was downgraded, the global view became a
projection, and the integrator disappeared. A rule may block only when it is
objective and breaking it leaves the repository wrong—not merely unconventional.

Drawing the whole workflow exposed holes prose had hidden. Removing the
integrator made the durable sequence explicit: owner ceremony, current trunk,
green rebased result, filled coherence audit, `status: done`, named self-merge.
The path register maps milestones and outcomes; `ACTIVE.md` alone projects live
registered paths.

## What the live pilot returned

Parallel paths did more than validate the model; they found its defects.

1. Cairn trimmed the leading status character from the first porcelain line,
   so locally dirty files could evade path and scope rules. Raw porcelain
   parsing and rename tests repaired it.
2. A generated view cannot see files that exist only on sibling branches. On
   2026-08-20 trunk truthfully matched its own files while falsely reporting no
   running paths. New accepted declarations now land as a registration-only
   trunk commit before implementation branches. CP-OPS-001, CP-MVP-011 and
   CP-MVP-012 are the finite pre-rule migration set.
3. A path is durable work; a chat is only an execution buffer. Every coherent
   step now refreshes its rolling brief, runs gates, commits and pushes
   immediately, reports the remote hash, and offers the next recorded action in
   a fresh session without an owner recap. Cairn advises when current HEAD is
   absent from its upstream without pretending local refs prove old push cadence.
4. CP-RENDER-REPAIRS found that the final state required by the protocol could
   not pass `branch-path`: the rule allowed only `running`, while closure
   requires `done` before merge. CP-OPS reproduced and repaired it. A done path
   with its recorded ceremony now passes; without the ceremony it still blocks.

## Closure and gates

The owner accepted the path with *"ok for all go for closure"* and chose to
finish in the same session because the restored worktree lived under `/tmp`.
The branch already contained `master == origin/master == cc78d2f`; the required
rebase was a no-op at `a495095`, so no published commit was rewritten and no
force-push was needed.

The filled coherence audit records drift repaired before merge: the done-branch
gate contradiction and one stale register sentence were corrected; ADR-012
owns the decisions; CP-MVP-011/012 build distinct Wikimedia product work. Cairn
self-tests and protocol check passed. Typecheck passed, all 78 test files passed
with 1,101 tests passing and 1 skipped, and the production build passed. The
first restricted test run was denied local loopback binds; rerunning the same
bare suite with loopback permission produced the green verdict. D08/D14 XML and
D14's 14-box/2-label geometry assertions also passed.

## What remains explicit

- Immediate historical push cadence cannot be reconstructed from final local
  refs; GitHub Activity is timeline evidence, while the branch is the recovery
  checkpoint.
- `base_commit` format is checked, not its prose-level accuracy.
- A coherence audit's existence is mechanical; its judgment deliberately is
  not a blocking oracle.
- An abandoned `running` path still has no dedicated terminal transition.
- CP-MVP-011 and CP-MVP-012 keep the finite registration exception until they
  merge; no new path may copy it.

No roadmap order changed. This labelled process path closes with its operating
detail, constitutional projections, decision record, tests, audit, ceremony,
journal and generated state aligned.
