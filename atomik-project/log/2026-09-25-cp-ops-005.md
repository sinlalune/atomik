# CP-OPS-005 — the kit's update

Opened 2026-09-22, closed 2026-09-25 at candidate
`3be8c125ac1ffc015811adce76f9390787112a7d`, the third, after two work units.
Opened because the installed release was already current while three of its
generated files were not: a declared root had moved and a transport had changed
since install, and nothing had regenerated what the kit builds from the
configuration.

## What changed

`npx cairn-protocol@1.1.0 update` — 7 written, 0 deleted. Five of the seven are
a regenerated date line. Two matter:

- **`.github/pull_request_template.md`** arrives. The kit plans it only under
  `transport.integration: pull-request`, which CP-OPS-003 S03 declared, so this
  repository had been closing requests by hand into a shape a file should have
  supplied. Request #7 is the first written into it.
- **`cairn/README.md`** stopped saying *"Nothing. The last update rewrote every
  file it owns"* in a repository with ten edited kit files.

Every edited kit file was kept, and ADR-023's held patch was verified untouched
under the command that decision is about — the file byte-identical, its
recorded digest still the release's, `linkExempt` present.

## What it found

Fifteen manifest digests changed at one release, one `sourceCommit` and one
unchanged configuration:

```text
  11  the date stamp                 6 untouched, expected digest re-rendered
                                     5 rewritten for nothing but their own date line
   2  ACTIVE.md, cairn.config.json   re-baselined to this host's bytes
   2  pull_request_template, README  real content
```

Every templated file is rendered with today's date, so the digest of what the
kit *would* write depends on when you ask: two runs on two days produce two
locks from one repository in one state. Filed as
[cairn PR #29](https://github.com/sinlalune/cairn/pull/29), with the two
re-baselines as a separate mechanism — `cairn.config.json` has no timestamp to
render, which is what proves the causes apart.

## What it cost

Two units and three candidates for one command, because almost nothing this
path wrote about the command was right the first time.

The record accounted for nine of the fifteen digests and called the two
smaller cases its finding. A first draft of the upstream note then swung the
other way and put all fifteen on the clock. Three figures were recalled rather
than measured. The definition of done asked the kit's generated page for a
count the kit does not produce, and had to be amended.

And S01 was committed and pushed carrying the output of a command that a
double-quoted shell string executed inside it — the fourth shell substitution
of the week and the first to reach an immutable record. S02 is the repair:
`type: repair`, binding `c0d9d7d` to `956290e`, both read with `git`. The
checker turned its blocking `record-integrity` finding into a stated advisory,
which is the protocol recognising a repair rather than exempting it. Its own
review then had to be **appended**, because by the time a reviewer asked for it
the record carrying the heading was already published.

The rule that removes the whole class: write records with a quoted heredoc and
pass values as `argv`; and write the review into the step record **before** the
commit, not after.

## What is left

Nothing of this path's. Atomik runs release 1.1.0 and diverges from it in one
file, `tools/cairn-check.mjs`, which ADR-023 records and which only a Cairn
change can retire — the `links` exemption asked for in cairn PR #23.
