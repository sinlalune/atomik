# CP-OPS-002 — Cairn 2.0

Opened 2026-08-24 from an audit that found one failure mode wearing six faces:
Cairn wrote rules forward and never drained the state that predated them, and
three checks certified statements that were false on the trunk. Closed
2026-09-02 at candidate `1f4ba09924860bea1de181400c4eba577980429f`, the third, after forty-eight work units.

## What changed

- **The rules are honest.** Every enforcement defect found on the way was a
  proxy predicate substituted for the sentence the rule states — a filename for
  a declaration, a directory entry for its files, the trunk's copy for the
  candidate's, a count for a judgement, the host's branch variable for the
  tree's branch, the previous push for the trunk. Each was replaced by the
  predicate the sentence names, with an adversarial fixture that fails first.
- **The protocol is extracted.** A canonical v0.2 specification with a concept
  wiki and an implementation reference; a portable path convention and
  execution protocol separated from one explicit Atomik binding; an executable
  `cairn.config.json`; `cairn-init`, which installed a research-paper workspace
  that reached `done` on its second run; a fixture suite of 277 subtests.
- **Rewriting is gone.** ADR-022 forbids rewriting a published path branch, so
  the retention namespace, its generations and their repairs left with the
  rebase that required them; a current base is reached by merging the trunk in.
- **The record is born sliced.** ADR-020 made context weight a constraint; this
  path's own record is one folder, one file per step, a plan read only when
  planning, and a brief with pinned reading.
- **The manifesto is applied.** The owner's manifesto and project note are in
  `docs/cairn/`, and the convergence record measures the protocol against them:
  a light entry chain over a heavy body, one and a half of six stages covered,
  and a Cairn 1.0 shape — six chapters on the chronology, about twenty rules,
  about thirty concepts, one folder per path, pull-request integration, Agent
  Skills, `npx cairn`. The owner ruled on all twenty-four decisions.

## What the closure itself found

Three candidates were needed. The first was voided when CI was read and found
red since S08u: the checker trusted the host's branch variables inside the
fixture repositories (S09d). The second was voided when the integration pull
request compared the branch with the trunk and found twenty-six immutable
session records edited at the path's own first step, invisible to every push
run because the workflow compared each push with the one before (S09e). Both
are the path's subject arriving at its own door, and both are repaired with a
fixture or a record.

## What it cost

Forty-eight units over ten days; two superseded specification attempts before
the canonical one; one retention design accepted, implemented and removed
within two days when the question one level up was asked; three closures.

## Deviations, stated

- Ruling 11 said no further protocol work in this path. S09d and S09e are
  protocol work: a red gate on the candidate is not integrable, and both
  defects were in the control plane. They are the exceptions and are recorded.
- The trunk now requires a pull request while the binding declares
  `manual-git`; the integration went through a pull request from a non-path
  branch, and the binding is a named defect for the next path.
- The lightweight route's three reliefs, sixteen blocking rules without a
  fixture, pilot findings 7 and 16, `cairn-new`, `cairn-close`, the update path,
  forward-plan item 12, a `ci-unread` advisory, the correction-record remedy
  with no predicate, and `resolveBase` on non-path branches are named debts,
  all sent to the genesis of the protocol's own repository.

## What comes next

The genesis of the `cairn` repository, opened with the convergence record and
the manifesto as its input; the authority over the portable protocol moves once,
at its first commit, and this repository becomes its first adopter.
